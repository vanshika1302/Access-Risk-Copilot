Access Risk Copilot

Access requests are approved or denied by a person. Which ones deserve a second look? Three SQL controls flag risky requests, a model scores the likelihood of denial, and an LLM writes a short audit finding that is checked against the SQL facts.

Real data, anonymised IDs. Every column is an opaque ID, so no resource, role or department has a name here. The separation-of-duties conflict pairs are an illustrative, seeded list I authored, not real policy.

1. SQL controls

Three controls in DuckDB (sql/controls.sql). Denial rates use only dev and test rows, which no control or model was built from.

Denial rate of flagged requests vs all held-out requests

2. Predicting denied requests

Logistic regression on one-hot IDs, then a random forest. Chosen on dev, test scored once. Denied is the rare class (5.8%), so AUC is the headline.

3. AI audit findings, checked against SQL

An LLM (Claude via headless claude -p, all tools disabled) writes one finding per flagged case. A scorer then checks every claim and number against the SQL facts. A silent error is a wrong finding that did not say it was uncertain.

Limitations

  • Test findings: 60 cases, 0 silent errors. With zero events in 60, the true rate could still be about 5% (rule of three).
  • The number scorer misses a sentence whose numbers are all real but misrelated (found once on dev). The free-text judge catches blatant injected errors (24 of 24) but its recall on subtle ones is not measured, and it missed a garbled sentence an earlier version caught.
  • The template baseline is correct by construction, so the model is not "beating" it on accuracy; it adds readable explanation.
  • Controls are rules I wrote on anonymised IDs. Unusual access flags 7.6% of requests (an earlier, looser version flagged 26% and was replaced); its lift is weakest in large departments.
  • SoD flags only requests that were approved, so their denial rate is 0 by design: they are policy conflicts, not denial predictors.
  • Findings come from Claude Code headless mode on a subscription, not the API. No API key was used.
